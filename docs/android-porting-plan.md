# Yovoice Android 完整移植计划与交付门禁

## 目标

把原版 Yovoice 的核心业务流程迁移到 Android，保持本地运行，不依赖用户自建服务器或电脑。APK 是应用程序与 Android 原生运行时的安装包；模型权重按需从模型仓库下载到手机本地，下载后离线使用。

## 现状与已发现的问题

- 原仓库的产品架构是 React UI → macOS/Windows 原生宿主 → Go Workbench 服务 → audio.cpp 推理子进程，并使用 FFmpeg 做音视频转换。
- 原工程的桌面构建产物包含桌面平台专用宿主和运行时，不能直接塞进 Android APK。
- 先前 Android 原型只实现系统 TTS 试听与本地音频播放，没有接入 Go Workbench、audio.cpp、FFmpeg 或模型管理。
- 先前 APK 的 CI 只验证了 Kotlin 编译和 APK 打包，没有做模拟器启动或真机启动验证，因此“BUILD SUCCESSFUL”不代表安装后能正常打开。
- 启动代码存在初始化时序风险：TTS 回调可能在界面状态控件准备好之前访问状态控件。当前修复为先创建界面，再初始化 TTS，并增加生命周期与异常保护。仍需在模拟器和真实设备验证。

## 交付规则（必须全部通过）

禁止在以下项目完成前生成对外交付 APK：

1. **启动稳定性**
   - 冷启动、热启动、前后台切换、旋转/进程重建无闪退。
   - Android 版本和 ABI 检测正确；权限和文件选择流程可用。
2. **原生推理运行时**
   - 为 Android arm64 建立可复现的 NDK/CMake 构建。
   - 验证 audio.cpp 在 Android CPU 后端运行；GPU/Vulkan 后端仅在设备能力确认后启用。
   - 移植 Go Workbench 的 Android 生命周期、存储目录、任务取消和状态通知，不能直接照搬桌面进程管理。
   - FFmpeg 或 Android MediaCodec 的导入、解码、编码路径完成验证。
3. **模型目录与下载**
   - 读取原项目模型目录数据，展示全部模型、精度、版本、体积、许可、依赖、输入要求和最低设备条件。
   - 点击下载后使用 Android DownloadManager/受控下载器下载到应用私有模型目录；支持进度、暂停、续传、取消、断点恢复。
   - 下载结束逐文件校验 SHA-256 和文件大小；多文件模型全部通过校验后才登记为已安装。
   - 下载空间不足、网络中断、文件损坏、存储权限变化时给出可恢复提示。
   - 不把数 GB 至十几 GB 的权重打包进 APK；APK 内只放目录元数据和必要程序资源，模型按需下载。
4. **模型识别与加载**
   - 通过模型 ID、版本、精度、清单和 GGUF 元数据识别模型；不能仅凭文件名猜测。
   - 加载前检查 ABI、CPU 指令集、可用内存、可用存储、运行时版本和模型依赖。
   - 单模型加载、卸载、切换、内存回收、进程崩溃恢复完成。
   - 每个模型必须有真实推理冒烟测试，不能仅显示“已下载”或“已加载”。
5. **产品功能**
   - TTS/声音克隆、ASR/字幕、故事配音、音乐生成、音轨分离、MIDI/乐谱、项目和作品历史按模块迁移。
   - 每个按钮都有真实动作；不支持的设备/模型显示明确原因，不出现空壳按钮。
6. **测试与发布**
   - Kotlin 单元测试、Go 单元测试、C++ 原生测试、模型下载/校验测试通过。
   - Android 模拟器启动测试通过。
   - 至少在目标手机类别（Android arm64、8GB RAM）执行冷启动、模型下载、模型加载、实际推理、音频播放测试。
   - 最终 APK 安装、启动、功能冒烟和 SHA-256 校验全部通过后，才上传交付。

## 模型覆盖策略

原版模型目录中的大模型和小模型都会进入 Android 模型目录的可见清单，但“可见/可下载”不等于“当前设备可运行”。每个模型必须有 Android 运行时适配状态：

- 已验证可运行：可下载、加载和推理。
- 可下载但设备不兼容：显示不兼容原因，不允许误导性加载。
- Android 后端尚未适配：显示待适配，不提供虚假的“下载后即可使用”承诺。
- 受许可限制：展示原模型许可证和用途限制后再下载。

8GB RAM 设备优先验证小型 CPU 模型；大模型即使可下载，也可能因内存、存储、算力或模型后端限制无法运行。应用需在下载前给出设备检查结果，并允许用户自行决定是否继续下载可兼容的大模型。

## 分阶段实施

### 阶段 A：启动与 Android 工程
- 修复 TTS 初始化时序和 Activity 生命周期。
- 加入 Android 单元测试、模拟器启动测试和崩溃日志采集。
- 将 APK 打包从日常 push CI 中移除，改为人工验证门禁。

### 阶段 B：Android 原生引擎
- 评估并构建 audio.cpp Android arm64 CPU runtime。
- 定义 Kotlin ↔ JNI ↔ C++ 的稳定接口和错误码。
- 移植音频输入输出、临时文件、取消和进度事件。
- 再接入 Go Workbench 的可移植业务层。

### 阶段 C：模型中心
- 复用原始 catalog、模型 URL、版本、SHA-256 和多文件包规则。
- 实现设备存储检查、下载队列、断点续传、校验和原子安装。
- 实现模型发现、识别、加载、卸载与状态持久化。

### 阶段 D：端到端功能
- 先打通一个轻量 TTS 模型的下载 → 校验 → 加载 → 中文朗读 → WAV 输出。
- 通过后再扩展语音克隆、ASR、故事配音。
- 音乐、音轨分离和 MIDI 使用各自的模型与资源要求独立适配，不把桌面端支持误写成 Android 已支持。

### 阶段 E：交付
- 自动化测试与目标设备测试全部通过。
- 只在手动发布工作流中构建 APK，并附版本、功能清单、兼容范围和 SHA-256。

## 当前状态

当前仍处于阶段 A 的修复与验证；尚未达到 APK 发布门禁，不应生成或交付新的 APK。
